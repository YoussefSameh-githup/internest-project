{% trans "How a skill becomes “verified”" %}

{% trans "Students can list any skill, but it is shown to companies as verified only after one of these:" %}

  • {% trans "A skill test passed with no weak sub-skill. A person from our team confirms it first when the test included a practical task or a server-side signal (very fast answers, or a written answer nearly identical to another student's)." %}
    • {% if rules.freelance_auto %}
  • {% trans "Freelance work the student did, checked automatically against the student's own profile." %}
    • {% else %}
  • {% trans "Freelance work the student did, reviewed by our team." %}
    • {% endif %}
  • {% trans "A certificate, reviewed by our team." %}
  • {% trans "A course from a partner we verified, completed on Internest and confirmed by that partner." %}

{% trans "A high score alone never counts: a student who scores well but is weak in one sub-skill is not verified. Every count of “verified candidates” on Internest uses this one rule. In rare cases our team sets a skill as verified by hand; the evidence report then says so." %}

{% trans "The skill test" %}

  1. {% trans "Timed questions." %} {% blocktrans with s=rules.question_seconds %}{{ s }} seconds per question, easy to hard. We prefer questions the student hasn't seen before and reuse older ones only when there aren't enough. The timer and the grading run on our server, not in the browser.{% endblocktrans %}
  2. {% trans "Where the questions come from." %} {% trans "When our AI provider is available, an AI model writes a fresh set of questions for the attempt, with their answer key and sub-skill labels; otherwise we use our saved question bank. Generated questions are added to the bank without a person checking each one first." %}
    3. {% if numbers.practical_skills %}
  3. {% trans "A practical task." %} {% blocktrans with n=numbers.practical_skills m=numbers.skills_with_tests mins=rules.practical_minutes %}{{ n }} of the {{ m }} skills with a test end with a {{ mins }}-minute real task (for example a query, a plan or a clause), scored against a points rubric.{% endblocktrans %}
    4. {% endif %}
  4. {% trans "Human review." %} {% blocktrans with d=rules.review_days %}A person from our team sets the final grade of every practical answer and looks at passing attempts that raised a server-side signal. We aim to do this within {{ d }} working days. An AI tool may suggest a grade; it never decides.{% endblocktrans %}
  5. {% trans "Retakes." %} {% blocktrans with h=rules.cooldown_hours %}A failed or ended attempt can be retaken after {{ h }} hours, with different questions where the bank allows.{% endblocktrans %}

{% trans "Companies with a Hiring Pass can add their own screening task to an opportunity and score it themselves, so they can test exactly what the role needs." %}

{% trans "Cheating prevention, without spying" %}

  • {% trans "Copy, paste and right-click are blocked inside the test." %}
  • {% blocktrans with n=rules.focus_limit h=rules.cooldown_hours %}Automatic rules: an answer that was pasted, or typed in a way that looks injected or machine-generated, scores zero; two such answers, or leaving the test window more than {{ n }} times, end the attempt (it can be retaken after {{ h }} hours). No person reviews these automatic decisions.{% endblocktrans %}
  • {% blocktrans with s=rules.fast_seconds p=rules.similarity_percent %}Server-side signals: many correct answers in under {{ s }} seconds (faster than a person can read the question), or a written answer about {{ p }}% identical to another student's (repeating the question's wording doesn't count), send a passing attempt to a reviewer instead of verifying it straight away.{% endblocktrans %}

{% trans "Skill tests never turn on the camera or microphone, and we don't fingerprint or track devices. The speed and similarity signals never fail anyone on their own: a person decides." %}

{% trans "What verification cannot promise" %}

  • {% trans "No online test is cheat-proof. Someone could still get help from another person; our checks make it harder and send doubtful passing attempts to a person." %}
  • {% trans "Not every skill has a practical task yet, and skills that have one have only one, so retakes can see the same task." %}
  • {% trans "AI-written questions and answer keys can contain mistakes." %}
  • {% trans "Automatic rules can be wrong, for example with an unusual keyboard or connection, and they can zero an answer or end an attempt without a person looking." %}
  • {% trans "A verified skill shows what the student demonstrated on that day. It is not a guarantee of job performance, and we don't guarantee hires." %}

{% trans "Candidate privacy and data protection" %}

{% trans "Who sees what" %}

  • {% trans "Students choose whether to appear in the Talent Pool and can turn it off at any time." %}
  • {% trans "In the Talent Pool, verified companies without a Hiring Pass see summaries without name, university, photo or contact details: major, study year and verified skills with a score range." %}
  • {% trans "In the Talent Pool, companies with a Hiring Pass see name, university, bio, portfolio link, verified skills with exact scores and percentiles, and verified work experience." %}
  • {% trans "A company a student applies to sees the student's name, university and verified skills." %}
  • {% trans "A university the student chooses to share with sees the student's skill report." %}
  • {% trans "Phone, email and CV are shared only after the student applies and agrees to share them, and the company shortlists or accepts them." %}
  • {% trans "Answers to a company's screening task are visible only to that company and our team." %}

{% trans "How data is protected" %}

  • {% trans "Encrypted connections (HTTPS) everywhere; passwords are stored only as salted hashes." %}
  • {% trans "CVs, certificates, receipts and work samples are served only to the people allowed to see them." %}
  • {% trans "We never see or store card numbers." %}
  • {% trans "Students can download their data or delete their account from their profile at any time; companies ask us and we act within 30 days." %}

{% trans "We are reviewing our obligations under Egypt's Personal Data Protection Law (Law No. 151 of 2020) and, where it applies, the EU GDPR. We don't claim formal compliance until that review is complete." %} {% trans "Privacy policy" %}
